# 运行与测试指令

以下命令用于当前学习项目。每个代码块都标明工作目录，环境变量要在运行对应进程的同一个终端设置。换电脑后，将 `/Users/tankaiwen/go/src/feed-system-learning` 替换为自己的仓库路径。

RabbitMQ 本地设施的启动、管理控制台和停止命令见 [`infra/rabbitmq/README.md`](../infra/rabbitmq/README.md)。后端启动时会连接 RabbitMQ 并声明 Exchange、Queue 和 Binding；互动通知业务目前仍由原有数据库逻辑同步处理。

## 一、首次准备

需要 Go 1.24.5 或更高版本、Node.js/npm、Python 3.10 或更高版本、MySQL、Redis、Docker Desktop（含 Docker Compose）和 Google Chrome。查看本机工具：

```bash
go version
node --version
python3 --version
mysql --version
redis-cli --version
```

安装前端与测试依赖，仅首次或依赖变更后执行：

```bash
cd /Users/tankaiwen/go/src/feed-system-learning/frontend
npm ci

cd /Users/tankaiwen/go/src/feed-system-learning
python3 -m venv .venv
.venv/bin/python -m pip install -r tests/requirements.txt
```

Python 命令统一使用仓库自己的 `.venv/bin/python`，无需每次激活环境。Allure 报告还需要本机有 `allure` 命令，可用 `allure --version` 检查。

## 二、日常启动项目

先确保本机 MySQL、Redis 和 RabbitMQ 已启动。RabbitMQ 使用仓库中的 Docker Compose：

```bash
cd /Users/tankaiwen/go/src/feed-system-learning
docker compose -f infra/rabbitmq/docker-compose.yml up -d
docker compose -f infra/rabbitmq/docker-compose.yml ps
```

等待 RabbitMQ 状态为 `healthy`，再启动后端。MySQL 和 Redis 检查：

```bash
mysql -h 127.0.0.1 -P 3306 -u root -e 'SELECT 1;'
redis-cli -h 127.0.0.1 -p 6379 PING
```

Redis 应返回 `PONG`。下面的 MySQL 示例按本机 root 无密码配置编写；若设置了密码，MySQL 命令加 `-p`，并将 DSN 中的 `root@tcp` 改为 `root:实际密码@tcp`。

**终端 1：启动后端。** 首次创建数据库，后端会自动建立账号表和视频表。

```bash
mysql -h 127.0.0.1 -P 3306 -u root -e 'CREATE DATABASE IF NOT EXISTS feed_system_learning CHARACTER SET utf8mb4;'

cd /Users/tankaiwen/go/src/feed-system-learning/backend
export MYSQL_DSN='root@tcp(127.0.0.1:3306)/feed_system_learning?charset=utf8mb4&parseTime=True&loc=Local'
export RABBITMQ_URL='amqp://feeddev:feeddev-local-password@127.0.0.1:5672/'
export REDIS_ADDR='127.0.0.1:6379'
export REDIS_PASSWORD=''
export REDIS_DB='0'
export JWT_SECRET='local-only-feed-learning-signing-secret'
export ACCESS_TOKEN_TTL='15m'
export VIDEO_CACHE_TTL='5m'
export AUTHOR_VIDEO_CACHE_TTL='1m'
export FEED_CACHE_TTL='30s'
export CACHE_TIMEOUT='200ms'
export HTTP_ADDR=':8081'
export UPLOAD_DIR="$PWD/.run/uploads"
export PUBLIC_BASE_URL='http://127.0.0.1:8081'
go run ./cmd
```

Redis 配置了密码时，填写 `REDIS_PASSWORD`。示例 JWT 密钥仅用于本地学习；设置固定密钥可避免每次重启都因为临时密钥变化而使旧 access token 失效。

**终端 2：启动前端。** 保持终端 1 运行。

```bash
cd /Users/tankaiwen/go/src/feed-system-learning/frontend
API_PROXY_TARGET='http://127.0.0.1:8081' \
VITE_ENABLE_CHUNK_UPLOAD='false' \
  npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

浏览器打开 <http://127.0.0.1:5173/account/register> 注册账号，登录后进入 <http://127.0.0.1:5173/video> 发布视频。

**终端 3：检查后端。**

```bash
curl --fail http://127.0.0.1:8081/healthz
```

应返回 `{"status":"ok"}`。前端请求 `/api/...`，Vite 会去掉 `/api` 前缀，再转发到后端。例如 `/api/account/login` 对应后端 `/account/login`。

## 三、启动独立测试环境

测试会创建账号、视频记录和上传文件。使用下面的专用 MySQL 数据库、独立 Redis 进程及上传目录，与日常数据分开。

| 用途 | 日常环境 | 测试环境 |
| --- | --- | --- |
| 后端 | `8081` | `8082` |
| 前端 | `5173` | `5174` |
| MySQL 数据库 | `feed_system_learning` | `feed_system_pytest` |
| Redis | `6379`，DB 0 | `6380`，DB 0，独立进程 |
| 上传目录 | `backend/.run/uploads` | `backend/.run/pytest-uploads` |

**测试终端 1：启动临时 Redis。** 此进程不保存测试数据，保持终端运行。

```bash
redis-server --bind 127.0.0.1 --port 6380 --save '' --appendonly no
```

如果提示端口已占用，先确认占用进程；改用其他空闲端口时，同时修改测试后端和 pytest 的 Redis 地址。

**测试终端 2：启动测试后端。**

```bash
mysql -h 127.0.0.1 -P 3306 -u root -e 'CREATE DATABASE IF NOT EXISTS feed_system_pytest CHARACTER SET utf8mb4;'

cd /Users/tankaiwen/go/src/feed-system-learning/backend
export MYSQL_DSN='root@tcp(127.0.0.1:3306)/feed_system_pytest?charset=utf8mb4&parseTime=True&loc=Local'
export RABBITMQ_URL='amqp://feeddev:feeddev-local-password@127.0.0.1:5672/'
export REDIS_ADDR='127.0.0.1:6380'
export REDIS_PASSWORD=''
export REDIS_DB='0'
export JWT_SECRET='local-only-pytest-signing-secret'
export ACCESS_TOKEN_TTL='15m'
export VIDEO_CACHE_TTL='5m'
export AUTHOR_VIDEO_CACHE_TTL='1m'
export FEED_CACHE_TTL='30s'
export CACHE_TIMEOUT='200ms'
export HTTP_ADDR=':8082'
export UPLOAD_DIR="$PWD/.run/pytest-uploads"
export PUBLIC_BASE_URL='http://127.0.0.1:8082'
go run ./cmd
```

**测试终端 3：启动测试前端。** 仅跑接口测试时可以省略。

```bash
cd /Users/tankaiwen/go/src/feed-system-learning/frontend
API_PROXY_TARGET='http://127.0.0.1:8082' \
VITE_ENABLE_CHUNK_UPLOAD='false' \
  npm run dev -- --host 127.0.0.1 --port 5174 --strictPort
```

**测试终端 4：设置测试配置。** 后面的 pytest 命令都在这个终端执行。

```bash
cd /Users/tankaiwen/go/src/feed-system-learning
export FEED_API_BASE_URL='http://127.0.0.1:8082'
export FEED_WEB_BASE_URL='http://127.0.0.1:5174'
export FEED_TEST_REDIS_ADDR='127.0.0.1:6380'
export FEED_TEST_REDIS_PASSWORD=''
export FEED_TEST_REDIS_DB='0'
export FEED_UI_HEADLESS='1'
export FEED_REPORT_RUN="$(date +%Y%m%d-%H%M%S)-$$"
export FEED_UI_ARTIFACT_DIR="$PWD/reports/pytest/$FEED_REPORT_RUN"
curl --fail "$FEED_API_BASE_URL/healthz"
```

每次新建一轮报告时，重新设置 `FEED_REPORT_RUN` 和 `FEED_UI_ARTIFACT_DIR`。不同终端不会自动共享刚刚 `export` 的变量，因此这里再次完整设置测试所需配置。

## 四、执行 pytest 和 Selenium

下面的命令任选一条执行。

只跑 API 测试：

```bash
.venv/bin/python -m pytest tests/api -q \
  --alluredir="reports/allure-results/$FEED_REPORT_RUN"
```

只跑 Selenium 页面测试：

```bash
.venv/bin/python -m pytest tests/ui -q \
  --alluredir="reports/allure-results/$FEED_REPORT_RUN"
```

API 和页面一起跑：

```bash
.venv/bin/python -m pytest tests/api tests/ui -q \
  --alluredir="reports/allure-results/$FEED_REPORT_RUN"
```

显示 Chrome 窗口，只观察“登录 → 上传 → 发布 → 播放”这一条用例：

```bash
FEED_UI_HEADLESS=0 .venv/bin/python -m pytest \
  'tests/ui/test_video_pages.py::test_publish_and_play[cover.png]' -v \
  --alluredir="reports/allure-results/$FEED_REPORT_RUN"
```

默认使用无头 Chrome。首次运行时 Selenium 可以自动管理驱动；如果驱动下载失败，可用 `FEED_UI_CHROMEDRIVER` 指定本机 ChromeDriver 路径，`FEED_UI_CHROME_BINARY` 指定 Chrome 可执行文件路径。驱动需与本机浏览器版本匹配。

API 大文件用例会真实上传超过 200 MiB 的内容；运行完整测试时保留足够的临时磁盘空间。缓存用例需要 `redis-cli`，缺少 Redis 测试地址或 DB 配置时会跳过，跳过不表示缓存验证成功。

## 五、查看 Allure 报告

在执行 pytest 的同一终端打开本轮报告：

```bash
allure serve "reports/allure-results/$FEED_REPORT_RUN"
```

也可以生成 HTML 报告并打开：

```bash
allure generate "reports/allure-results/$FEED_REPORT_RUN" \
  --output "reports/allure-report/$FEED_REPORT_RUN" --open
```

Allure 包含测试步骤、失败页面截图、HTML 和 HTTP 错误记录。发布成功的页面截图及网络错误 JSON 也会保存在 `reports/pytest/<本轮编号>/`。

## 六、其他检查与停止

Go 常规检查与前端构建：

```bash
cd /Users/tankaiwen/go/src/feed-system-learning/backend
go test ./...

cd /Users/tankaiwen/go/src/feed-system-learning/frontend
npm run build
```

真实 MySQL/Redis 登录态故障与并发测试需要单独提供连接配置。在上面的测试 Redis 仍运行时执行：

```bash
cd /Users/tankaiwen/go/src/feed-system-learning/backend
FEED_TEST_MYSQL_DSN='root@tcp(127.0.0.1:3306)/feed_system_pytest?charset=utf8mb4&parseTime=True&loc=Local' \
FEED_TEST_REDIS_ADDR='127.0.0.1:6380' \
FEED_TEST_REDIS_PASSWORD='' \
FEED_TEST_REDIS_DB='0' \
  go test -race ./internal/account -run TestSessionCache -v
```

在各自运行服务的终端按 `Ctrl+C` 停止前端、后端、临时 Redis 或 Allure。测试 MySQL 数据和上传文件会保留，便于检查；临时 Redis 没有开启持久化。测试不需要清空日常 Redis。

## 七、常见问题

| 现象 | 检查方式 |
| --- | --- |
| `请设置MYSQL_DSN` | 在运行 `go run ./cmd` 的同一个终端设置变量。当前程序直接读取环境变量，不会自动加载 `.env`。 |
| `Redis 连接失败` | 用 `redis-cli -h 127.0.0.1 -p 对应端口 PING` 检查；确认端口和密码一致。 |
| `address already in use` 或 Vite 端口占用 | 用 `lsof -nP -iTCP:8082 -sTCP:LISTEN` 查看占用；检查前端时，将命令中的 `8082` 换成 `5174`。 |
| 访问后端路径出现 404 | 后端直连地址没有 `/api` 前缀；浏览器通过 Vite 代理时才使用 `/api`。 |
| 发布时请求 `/video/chunk/init` 并返回 404 | 关闭 `VITE_ENABLE_CHUNK_UPLOAD`，重启 Vite。当前后端已实现普通上传，分片上传待实现。 |
| `ModuleNotFoundError: allure` 或 `selenium` | 用 `.venv/bin/python -m pip install -r tests/requirements.txt` 安装，再用同一个解释器运行 pytest。 |
| 关注流或点赞榜接口出现 404 | 这些业务尚未实现；最新视频流、点赞、评论、收藏和关注关系接口已接入。 |

本机如果因为遗留 npm 代理而无法安装前端依赖，可以仅对这次命令覆盖代理和镜像设置：

```bash
cd /Users/tankaiwen/go/src/feed-system-learning/frontend
npm ci --registry=https://registry.npmjs.org --replace-registry-host=always \
  --proxy=null --https-proxy=null --no-audit --no-fund
```

测试文件与覆盖说明见 [tests/README.md](../tests/README.md)。
